A cycler that only counts what it can prove

An automated plug/unplug rig that quantified receptacle wear on a new electrosurgical controller: 7,500 verified cycles per receptacle, unattended, when no test system for it existed.

Outcome7,500-cycle endurance data per receptacle, new design showed minimal wear vs. legacy; vendor spring substitution caught in preliminary runs
My roleSole designer and builder: mechanism, pneumatics, PCB, firmware, protocol
ConstraintsNo existing fixture; runs must be unattended; wear must land on the receptacle only
SkillsPneumatics, KiCad, Arduino Nano ESP32, Hall sensing, test protocol design

Why it exists

The controller's handpiece receptacle sees a plug inserted and removed many times over its service life. The program needed to know how the new receptacle wore compared with the legacy design, and whether cycling produced any electrical failure mode. Doing it by hand is neither repeatable nor practical at thousands of cycles, and no fixture existed.

I set four requirements: count only verified full strokes, put all wear on the receptacle (the plug is the consumable), reproduce natural plug-in motion rather than a rigid press-fit, and run unattended while reporting state at a glance.

The rig ran reliably through its full protocols. The new receptacle showed minimal wear relative to the legacy design, and the data was documented and shared with the full engineering team as input to design verification. The most useful catch came before formal testing: contact pad contamination in my preliminary runs traced back to an undocumented vendor spring substitution with a degrading coating, which let the team drive a corrective action before it reached the formal campaign.

Technical details

A double-acting pneumatic slide provides the linear motion. Four ASCO solenoid valves, two supply and two exhaust, are switched through a relay bank so each direction has its own controlled fill and vent. Flow regulators on each side set stroke speed independently, which is how insertion was tuned to feel like a human plug-in rather than a slam. The receptacle sits on a spring mount so it can float slightly during engagement and the plug finds its own alignment.

The controller is an Arduino Nano ESP32 on a custom KiCad board that replaced the original breadboard harness once the logic was proven. Firmware sequences the valves, reads both Hall sensors, and only increments the counter when a stroke is confirmed at both ends. An LCD shows direction, pause state, Hall status, and cycle count.

ActuationPneumatic air slide, double-acting, speed set by inline flow regulators
Valving4x ASCO solenoid valves (2 supply, 2 exhaust) driven by a 4-channel relay bank
ControllerArduino Nano ESP32 on a custom KiCad PCB
Stroke verificationHall-effect sensors at extended and retracted positions; both required per counted cycle
Cycle timeAbout 3.5 s; a 7,500-cycle run is roughly 7 hours unattended
Protocol7,500 cycles per receptacle, auto-pause every 500 for plug swap; programmable to 10,000
Operator interfaceLCD: direction, pause state, Hall status, cycle count

What I would change

Log every cycle with a timestamp and both Hall transitions rather than a running count, so a wear curve can be plotted against cycle number after the fact. The ESP32 has the connectivity; the first version prioritized a trustworthy count.
